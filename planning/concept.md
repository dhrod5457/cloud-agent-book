# Concept

## 이 책이 해결하려는 핵심 문제

기존 소프트웨어 프로젝트는 사람이 문서를 찾고, 환경을 해석하고, 실행 방법을 추론하며 개발하는 것을 기본 전제로 한다.

AI Agent가 개발 과정에 직접 참여하면 다음 문제가 발생한다.

- 프로젝트 실행 방법을 Agent가 추론해야 한다.
- 개발환경을 재현하지 못한다.
- 외부 시스템이 없으면 테스트가 중단된다.
- 변경 가능한 영역과 금지 영역의 경계가 불명확하다.
- 여러 Agent가 동일 파일을 수정하면서 충돌한다.
- Agent의 완료 선언과 실제 완료 여부가 일치하지 않을 수 있다.
- 장기 작업의 상태가 대화 컨텍스트에만 남는다.
- Cloud Agent는 VPN, 내부 DB, HSM, Jenkins 등에 접근하지 못할 수 있다.
- 사람이 계속 작업을 지시하고 검증하면 자동화 효과가 제한된다.

이 책은 다음 질문에 답한다.

> AI Agent가 인간 개발자의 지속적인 개입 없이 저장소를 이해하고, 환경을 구성하고, 작업을 수행하고, 테스트하고, 결과를 검증할 수 있는 프로젝트는 어떻게 설계해야 하는가?

그리고 다음 질문으로 확장한다.

> 여러 AI Agent가 동시에 작업해도 프로젝트의 일관성과 품질을 유지할 수 있는 개발 구조와 프로세스는 무엇인가?

## 핵심 개념

이 책의 중심 개념은 **Agent Ready Software Engineering**이다.

Cloud Agent, Local Agent, Hybrid Agent는 이 상위 개념을 구현하는 실행 형태로 본다.

## 핵심 주장

> AI Agent를 잘 사용하는 것보다 AI Agent가 잘 작업할 수 있는 프로젝트를 만드는 것이 더 중요하다.

이를 다음 원칙으로 구체화한다.

- AI Agent에게도 명시적인 개발 인터페이스가 필요하다.
- 프로젝트의 환경, 규칙, 상태는 대화가 아니라 Repository 안에 명시적으로 존재해야 한다.
- Agent의 완료 여부는 설명이 아니라 자동 검증 결과로 판단해야 한다.
- 모듈화는 유지보수뿐 아니라 Agent 간 작업 충돌을 줄이기 위한 수단이 된다.
- Local Agent, Cloud Agent, Human, PM Agent가 각각 잘할 수 있는 영역을 분리해야 한다.

## 제품과 원칙의 관계

Claude Code, Codex, GitHub Copilot Coding Agent, Devin 등의 기능은 사례와 검증 대상으로 사용한다.

책의 본문은 특정 제품 사용법이 아니라 다음과 같은 지속 가능한 원칙을 설명한다.

- 재현 가능한 환경
- 명확한 프로젝트 계약
- 자동 검증
- 테스트 가능한 외부 의존성
- 병렬 작업 가능한 모듈 경계
- 명시적인 작업 상태
- 권한 및 신뢰 경계
- Agent 간 역할 분리와 orchestration
