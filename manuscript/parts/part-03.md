# Part III. Cloud 실행환경과 검증을 설계한다

클라우드에 보낼 작업을 골랐다면 다음 문제는 실행 준비다.

에이전트가 Session을 시작할 때마다 JDK, 브라우저, 의존 패키지, DB 도구를 설치한다면 작업보다 환경 준비에 더 많은 시간이 들 수 있다. 반대로 준비된 환경이 있어도 모든 실패를 에이전트에게 넘기면 결정론적으로 처리할 수 있는 빌드와 테스트까지 LLM 비용을 사용하게 된다.

이 Part에서는 클라우드 작업이 빠르게 시작하고, 필요한 경우에만 에이전트가 개입하도록 실행 경로를 만든다.

미리 준비한 실행환경과 캐시로 시작 비용을 줄이고, 정상 검증은 클라우드 실행기가 처리한다. 소스 코드는 브랜치나 Worktree로, 실행환경은 컨테이너나 VM으로, 결과는 결과물 경로로 분리한다. 병렬화할 때는 작업자 수보다 독립 작업과 결과 통합 비용을 먼저 본다.

핵심 흐름은 다음과 같다.

```text
Prepared Environment
→ Runner-first
→ Source / Runtime / Evidence Isolation
→ Independent Task Fan-out
→ Fan-in
```

이 구조가 만들어지면 클라우드 작업은 독립적으로 실행될 수 있다. 다음 Part에서는 이 독립 작업을 기존 개발 작업 흐름과 연결한다.
