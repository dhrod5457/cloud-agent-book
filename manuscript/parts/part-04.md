# Part IV. Local과 Cloud를 연결한다

독립 실행환경에서 작업을 잘 처리하는 것만으로는 실제 개발 작업 흐름이 완성되지 않는다.

개발자는 로컬에서 요구사항을 좁히고 시스템 구조와 내부 제약을 판단한다. 클라우드에서는 독립 작업과 검증을 수행한다. 결과는 다시 로컬로 돌아와 검토, 내부 환경 검증, 병합을 거친다.

이 Part에서는 이 이동 경계를 다룬다.

사람이 직접 작업을 정리해 클라우드로 보내는 경우에는 `Git + Task Contract`가 입력 경계가 된다. 클라우드에서 돌아오는 결과는 `Result SHA + Evidence + PR`로 연결한다.

같은 구조는 CI 실패, 검토 의견, 예약 실행 같은 이벤트에도 적용할 수 있다. 이벤트 자체가 에이전트 호출 명령은 아니다. 먼저 작업 후보로 만들고, 중복을 제거하고, 실행기나 도구로 끝낼 수 있는지 확인한 뒤 판단이 필요한 경우에만 에이전트를 호출한다.

```text
Human-driven
Developer → Task Contract → Cloud

Event-driven
CI / Review / Schedule → Task Candidate → Cloud
```

두 경로의 공통점은 같다.

> Git으로 작업 상태를 넘기고 검증 근거로 결과를 돌려받는다.

다음 Part에서는 이 구조를 하나의 실제 프로젝트 작업 흐름으로 합친다.
