# Part I. Cloud Agent를 이해한다

코딩 에이전트가 로컬에서 파일을 읽고 수정하는 것만으로는 클라우드 에이전트를 설명하기 어렵다.

클라우드 에이전트는 저장소와 독립 실행환경을 함께 사용한다. 빌드와 테스트를 실행하고, 장시간 작업을 비동기적으로 처리하며, 여러 작업을 서로 다른 실행환경에 나눠 맡길 수 있다.

이 Part에서는 먼저 클라우드 에이전트를 **원격 개발 작업자**로 정의한다. 이어서 로컬과 클라우드의 차이를 실행 위치와 접근 범위로 나누고, LLM이 판단하는 자원과 CPU / RAM / 디스크가 실행하는 자원을 구분한다.

마지막으로 독립 실행환경이 왜 장시간 작업과 병렬 실행에 의미가 있는지 살펴본다.

이 Part를 읽은 뒤에는 다음 질문을 구분할 수 있어야 한다.

```text
Cloud Agent는 Local Agent와 무엇이 다른가?
Compute와 LLM Token은 어떻게 다른가?
Cloud가 개발자의 대기시간을 어떻게 줄일 수 있는가?
어떤 병렬성이 실제 개발에 도움이 되는가?
```

다음 Part부터는 이 실행환경에 **어떤 작업을 보낼 것인지** 결정한다.
