# 서문

코드를 작성하고 도구를 실행하는 AI인 코딩 에이전트(Coding Agent)가 테스트를 실행하고 코드 변경을 검토해 달라는 요청인 풀 리퀘스트(Pull Request, PR)까지 만들 수 있게 되면서 개발자의 질문도 달라지고 있다.

처음에는 어떤 모델이 더 코드를 잘 쓰는지가 중요했다. 실제 프로젝트에 에이전트를 넣기 시작하면 다른 문제가 더 크게 보인다.

```text
이 작업을 내 개발환경에서 계속할 것인가?
아니면 Cloud에 넘길 것인가?
```

원격 실행환경에서 작업하는 클라우드 에이전트(Cloud Agent)를 단순히 `클라우드에서 실행되는 AI`로 보면 이 질문에 답하기 어렵다.

이 책에서는 클라우드 에이전트를 다음과 같이 본다.

```text
Cloud Agent
= LLM
+ Repository
+ Independent Execution Environment
+ CPU / RAM / Disk
+ Development Tools
```

즉 클라우드 에이전트는 대화만 하는 모델이 아니라 코드 저장소(Repository)와 실행환경을 받아 실제 개발 작업을 수행할 수 있는 원격 개발 작업자다.

이 관점으로 보면 클라우드 에이전트의 장점도 달라진다.

핵심 가치는 단순히 더 많은 토큰(Token), 즉 모델이 글을 처리하는 단위나 더 큰 모델에 있지 않다. 개발자 컴퓨터의 로컬(Local) 개발환경과 분리된 곳에서 장시간 작업을 실행하고, 서로 독립적인 여러 작업을 동시에 처리할 수 있다는 점이 중요하다. 개발자는 그동안 다른 일을 할 수 있다.

하지만 모든 작업을 클라우드로 보내는 것이 좋은 방법은 아니다.

아키텍처를 결정해야 하는 작업, 내부망과 실제 장비가 필요한 작업, 요구사항이 계속 바뀌는 작업, 개발자가 결과를 자주 확인하고 방향을 바꿔야 하는 작업은 로컬이 더 적합할 수 있다.

반대로 코드를 실행 가능한 형태로 만드는 빌드(Build), 테스트, 사용자 동작을 처음부터 끝까지 확인하는 E2E(End-to-End) 테스트, Docker 빌드 같은 작업은 실행 명령과 완료 조건이 분명하다면 클라우드 실행기(Cloud Runner)에 맡기기 쉽다. 재현 가능한 실패를 분석하고 제한된 범위의 코드를 수정하는 작업은 클라우드 에이전트 후보가 될 수 있다.

그래서 이 책의 중심 질문은 `어떤 Agent를 사용할 것인가`가 아니다.

> 이 작업은 로컬에서 해야 하는가, 클라우드로 보내야 하는가?

이 질문에 답하려면 모델 선택만으로는 부족하다.

작업의 범위와 모델이 읽고 판단에 쓰는 맥락 정보(Context)의 양을 함께 봐야 한다. 실행환경, Git 상태, 테스트 방법과 검증 근거(Evidence), 내부망 의존성, 병렬화 비용, 검토 비용도 고려해야 한다.

이 책은 그 판단을 실제 개발 작업 흐름 안에서 다룬다.

Java/Spring Boot 기반 `campus-platform` 예제를 사용하지만 특정 제품 사용 설명서는 아니다. GitHub Copilot cloud agent, OpenAI Codex, Claude 계열의 hosted agent 사례는 공통 실행 패턴과 설계 원칙을 확인하기 위한 근거로만 사용한다.

제품 이름과 기능은 바뀔 수 있다. 하지만 다음 문제는 계속 남는다.

```text
작업을 어떻게 나눌 것인가?
어디서 실행할 것인가?
어떤 상태를 넘길 것인가?
무엇으로 검증할 것인가?
어떤 결과를 받아야 하는가?
```

이 책에서는 다음 방향을 일관되게 유지한다.

- 실행기가 할 수 있으면 실행기에게 맡긴다.
- 에이전트는 판단과 수정이 필요한 구간에만 사용한다.
- 작은 작업과 적은 양의 맥락 정보를 전달한다.
- 원본 결과는 파일 등 결과물(Artifact)로 보존하고 필요한 정보만 에이전트에게 보여준다.
- Git을 로컬과 클라우드 사이에서 작업을 넘기는 경계로 사용한다.
- 병렬화의 대상은 에이전트가 아니라 독립 작업이다.
- 클라우드 이점이 사라지면 로컬로 돌아온다.

클라우드 에이전트는 로컬 개발을 없애지 않는다. CI와 실행기도 없애지 않는다.

오히려 각 역할을 더 분명하게 나누게 만든다.

이 책을 다 읽은 뒤에는 새로운 클라우드 에이전트 제품을 볼 때 기능 목록부터 확인하기보다 자신의 작업을 먼저 보고 다음을 판단할 수 있기를 바란다.

```text
이 설계는 Local에서 하자.
이 검증은 Cloud Runner로 보내자.
이 실패는 Cloud Agent에게 맡기자.
이 마지막 검증은 내부망에서 하자.
```

그 판단을 반복 가능한 개발 작업 흐름으로 만드는 것이 이 책의 목적이다.
